# Shoka 未決事項

## 1. 実装前に解決する検証事項

### 1.1 楽天Books APIの実データ

状態: 未検証

確認すること:

- APIキーとアクセスキーを取得して実際に著者検索できるか
- 東野圭吾を含む代表著者で総件数とページングが安定するか
- `outOfStockFlag=1`で絶版・品切れ相当の項目がどの程度返るか
- 書影、判型、発売日、出版社、内容紹介の欠損率
- 同じISBNまたは商品が重複するケース
- 著者名の区切り方と共著者表現

判断基準:

- 外部レスポンスを内部モデルへ無理なく正規化できる
- 代表著者で書影が一覧体験を成立させる割合で取得できる
- 欠損してもプレースホルダーと項目省略で破綻しない

### 1.2 単著・共著フィルター

状態: 未決

楽天APIの著者フィールドが役割を厳密に表現しない場合、監修・原作・翻訳などを完全には除外できない可能性がある。

検証後に次のどちらかを選ぶ。

1. 安全に判定できる表現だけを掲載する
2. 著者名を含む項目を広めに掲載し、役割誤判定を既知の制約として明示する

推奨は1。ただし正しい単著・共著まで多く欠落する場合は2を再検討する。

### 1.3 著者候補の生成

状態: 未決

楽天APIは独立した著者検索APIではなく、書籍検索結果から候補を導出する。次を検証する。

- 部分一致検索で候補を安定抽出できるか
- 共著者文字列を誤って一人の著者として扱わないか
- 同じ人物の表記揺れをどこまでまとめられるか
- 完全一致一件の判定が安全か

著者候補は名前だけ表示する決定を維持し、補助情報は実利用で必要になった場合だけ追加する。

### 1.4 Worker CPU上限

状態: 未検証

Cloudflare Workers無料枠のCPU 10ms内で、次が完了するか計測する。

- 楽天API複数ページのJSON解析
- 対象書籍フィルター
- 日付とISBNの正規化
- 全件ソートまたはseed付きシャッフル
- KVへのシリアライズ

超過する場合の検討順:

1. 変換処理の単純化
2. ページ単位キャッシュと遅延正規化
3. D1または別の無料枠構成
4. 有料Workersへの移行

MVPの運用費0円制約があるため、4は最後の選択肢とする。

### 1.5 masonryの視覚順と操作順

状態: 未検証

CSS GridとResizeObserverによる配置で、次を実機確認する。

- DOM順と視覚上の順序が利用者を混乱させない
- 画像読み込み後の移動が小さい
- 無限追加時に既存カードが大きく移動しない
- iOS Safariを含む対象ブラウザで安定する
- フォールバックの通常グリッドでも利用可能

アクセシビリティと安定性が損なわれる場合は、完全なmasonryより通常グリッドを優先する。

## 2. 公開前に確認する事項

### 2.1 楽天Web Service利用条件

- 書影の表示方法とキャッシュ可否
- 必要なクレジットまたはリンク表記
- APIレスポンスの保存期間
- レート制限と禁止事項
- APIキーの利用制限

利用規約と本仕様が衝突する場合は、利用規約を優先して設計を修正する。

### 2.2 Cloudflare標準ログ

- 無料枠で標準生成されるログ
- IPアドレスなどの保持有無
- 保持期間と無効化可否

アプリ独自の計測は実装しない。

### 2.3 Shokaの名称

- 現在は仮称
- 国内主要サービスとの明確な重複は簡易検索で見つからなかった
- 商標の正式調査は未実施
- 独自ドメインはMVP対象外

## 3. 将来検討

### 3.1 シリーズ表示

候補仕様:

- シリーズごとの見出し
- シリーズ内を読む順に表示
- シリーズ外作品を「単独作品」にまとめる
- 複数シリーズ所属の扱い

正確なシリーズ所属と読む順番を公開データだけで保証しにくいため、MVP対象外とした。導入時は自動取得、手動補完、対応著者限定のいずれかを再検討する。

## 4. 確定済みで再質問しない事項

- MVPは紙の本だけ
- 単行本と文庫などは別カード
- 初期表示はランダム
- 出版年表示は各版の刊行日を古い順
- シリーズはMVP対象外だが将来候補
- ログイン、利用計測、問い合わせ窓口なし
- 運用費0円
- Next.jsではなくVite、TanStack Router、Hono、Cloudflare Workersを採用
