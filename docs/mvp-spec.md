# Shoka MVP仕様書

## 1. 概要

Shokaは、著者名からその著者の紙の本を検索し、書影を中心とした一覧で眺める公開Webアプリである。

多作な著者に興味を持った読者が「どのような本があるのか」を短時間で俯瞰できることをMVPの価値とする。

## 2. 背景と目的

特定の著者を読み始めようとしても、刊行物が多い場合は何が存在するのかを把握しにくい。一般的な書店検索は販売や個別商品の発見が中心で、著者の刊行物全体を視覚的に眺める用途には最適化されていない。

MVPでは、次を達成する。

- 著者名から紙の刊行物を探せる
- 書影を並べた画面で刊行物の規模と全体像を把握できる
- ランダム表示で偶発的に本を発見できる
- 出版年表示で各版の刊行履歴を古い順に確認できる

## 3. 対象ユーザー

- 日本語の本を読む人
- 本が好きな人、または既に特定の著者へ関心がある人
- PCまたはスマートフォンから短時間で著作を眺めたい人

個人向けに作るものを、同じ関心を持つ人も利用できるよう公開する。大規模な商用サービスは想定しない。

## 4. 対象データの定義

### 4.1 対象

- 著者の国籍を問わず、日本国内向けに刊行された日本語の紙の書籍
- 単著および共著
- 単行本、文庫、新装版など、取得元が別商品として返す各版
- 小説、エッセイ、実用書、漫画、絵本など、ジャンルを問わない単体の書籍
- 絶版、品切れ、現在販売されていない本
- ISBNがない本も、データ源が単体の紙書籍として返せる場合は対象

### 4.2 対象外

- 電子書籍
- 監修、編集、翻訳、解説だけで関与した本
- 一編だけを収録したアンソロジー
- 全集セット、雑誌、ムック、音声商品
- 原書および海外版

### 4.3 一覧の単位

同じ内容でも、単行本、文庫、新装版などは統合せず別のカードとして表示する。一覧の単位は抽象的な作品ではなく、データ源が返す紙の刊行物に近い。

### 4.4 網羅性

楽天Books Book Search APIから取得できた対象書籍を全件表示する。現実に刊行された全書籍の完全網羅は保証しない。データ源と欠落可能性を画面上で明示する。

## 5. 主要ユーザーフロー

1. ユーザーがトップ画面で著者名を入力する
2. 入力停止から500ms後、またはEnter・検索ボタンで著者候補を検索する
3. 一致する著者候補から一人を選ぶ
4. 完全一致する候補が一人だけなら、候補選択を省略して著者ページへ進む
5. 著者ページをランダム表示で開く
6. ユーザーは書影をスクロールして眺める
7. 必要に応じて出版年表示へ切り替える
8. 書影を選択すると詳細ダイアログが開く

検索エンジンからの流入とSEOはMVPの対象外とする。

## 6. 機能要件

### 6.1 著者検索

- アプリ内検索だけを主要導線とする
- 入力停止から500ms後に自動検索する
- 日本語IMEの変換中は検索しない
- Enterまたは検索ボタンでは待機せず検索する
- 新しい入力が始まったら古い検索リクエストをキャンセルする
- 空文字と空白だけの入力は検索しない
- 著者候補には著者名だけを表示する
- 同姓同名を追加情報なしで識別できないことはMVPの既知の制約とする

### 6.2 著者ページ

- 著者名を表示する
- 取得対象の総件数を表示する
- 初期表示はランダムとする
- ランダム表示と出版年表示を切り替えられる
- 最初に約30冊を表示し、スクロールに応じて続きを自動読み込みする
- ページ番号によるページングは表示しない

### 6.3 ランダム表示

- ランダムモードへ入った時点で全件の順序を一度決める
- スクロール、追加読み込み、画面幅変更では順序を維持する
- 「もう一度混ぜる」操作でのみ再シャッフルする
- 年などの見出しは表示しない

### 6.4 出版年表示

- 各版そのものの刊行日を使う
- 年ごとの見出しを表示する
- 年は古い順に表示する
- 年内も刊行日の古い順に表示する
- 年見出しごとに独立したmasonryグリッドを表示する

不完全な刊行日は次の規則で扱う。

| 取得値   | 表示                   | ソート上の扱い                 |
| -------- | ---------------------- | ------------------------------ |
| 年月日   | 判明した年月日         | 実日付                         |
| 上旬     | 原文どおり             | 1日相当                        |
| 中旬     | 原文どおり             | 11日相当                       |
| 下旬     | 原文どおり             | 21日相当                       |
| 年月のみ | 判明した年月           | 同月の日付判明分の後           |
| 年のみ   | 判明した年             | 同年の月判明分の後             |
| 年不明   | 「不明」または取得原文 | 最後の「刊行年不明」セクション |

同じソート位置では、書名の五十音順、次にISBN順で安定化する。画面へ架空の年月日は表示しない。

### 6.5 書籍カード

- 視覚上は書影だけを表示する
- すべてのカードに書名のアクセシブルラベルを付ける
- 書影がない場合はプレースホルダー内に書名を表示する
- マウス、タッチ、キーボードで選択できる
- 選択すると詳細ダイアログを開く

### 6.6 masonryレイアウト

- 同一画面内の列幅はすべて揃える
- 画面幅に応じて列数を増減する
- 書影の縦横比を維持し、高さは可変とする
- PCとモバイルで機能差を設けない

### 6.7 詳細ダイアログ

次を表示する。取得できない項目は空欄ではなく行ごと省略する。

- 書影
- 書名
- 著者名（共著者を含む）
- 出版社
- 刊行日
- 判型
- ISBN
- あらすじ・内容紹介（取得できる場合のみ）

価格、在庫、レビューは表示しない。楽天Web Serviceの利用条件を満たすため、楽天の商品ページへの出典リンクは表示する。

### 6.8 ローディングとエラー

- 初回取得中はレイアウト移動を抑えるスケルトンを表示する
- 追加読み込み中は一覧末尾に読み込み状態を表示する
- 取得失敗時は簡潔なメッセージと再試行ボタンを表示する
- 技術的なエラー詳細をユーザー画面へ出さない

## 7. UI方針

- サービス名は「Shoka」
- 補足文は「著者の本を一覧で眺める」
- ライトテーマのみ
- 左レール、検索領域、メイン領域で同じ中立的な背景色を使う
- 操作UIの主張を抑え、書影を主役にする
- 左側に縦組みのサービス名と緑のグラデーション円を置き、上部の検索欄とその下の著者画面で構成する
- レイアウトの区切りにはボーダーを極力使わず、主に余白を使う
- PCとモバイルの両方で利用可能なレスポンシブUI

## 8. 非機能要件

### 8.1 性能

通常のモバイル回線を基準とする。

- キャッシュ済み著者：2秒以内に最初のカードを表示
- 未取得著者の初回検索：5秒以内に最初のカードを表示
- 残りはスクロールに応じて読み込む
- 外部データの反映遅延は最大24時間まで許容する

### 8.2 対応ブラウザ

- Chrome、Safari、Firefox、Edgeの現行版と一つ前のメジャーバージョン
- iOS Safari
- Android Chrome

Internet Explorerと古い端末固有ブラウザは対象外とする。

### 8.3 アクセシビリティ

- すべての操作をキーボードで実行できる
- 書影カードをスクリーンリーダーが書名として認識できる
- ダイアログをEscapeで閉じられる
- ダイアログ開閉時のフォーカスを適切に管理する
- 文字と背景のコントラストを確保する
- OS・ブラウザの動き軽減設定を尊重する

専門機関による監査と正式な適合宣言はMVP対象外とする。

### 8.4 プライバシー

- ユーザー登録とログインを設けない
- 読了、読みたい、お気に入りなどの個人データを持たない
- Cookieによる個人追跡をしない
- 利用分析、ページ閲覧数、検索成功率、エラー率、応答時間を含む独自計測を実装しない

ホスティング事業者が標準で保持する技術ログの有無と保持期間は、利用分析とは別に確認する。

### 8.5 規模と可用性

- 1日数百人程度までの個人運営を想定する
- 大規模アクセス、高可用性、常時稼働を保証しない
- 無料枠を超えた場合に一時利用不能となることを許容する

### 8.6 費用

- 運用費0円をMVPの制約とする
- Vercelの無料枠を使う
- 有料APIを使わない
- 無料の開発者登録とAPIキー発行は許容する
- 独自ドメインはMVP対象外とする

## 9. 運用方針

- データの訂正フォームと問い合わせ窓口を設けない
- データ源と完全性を保証しない旨を表示する
- ユーザー向けの手動キャッシュ更新機能を設けない
- `main`へ直接pushする。CIは当面導入しない
- push前に`pnpm check`を手動実行する
- 本番公開はVercelから明示的に行う

## 10. MVP対象外

- シリーズ分類と読む順番
- 電子書籍
- 読書記録、お気に入り、読みたい管理
- ログインとユーザーアカウント
- ダークモード
- SEOと検索エンジン流入施策
- 価格、在庫、レビュー
- 楽天以外の購入・図書館への導線
- 利用分析と独自監視
- データ訂正受付
- 独自ドメイン

将来候補は[未決事項](open-issues.md)に整理する。

## 11. MVP受け入れ条件

- 著者名を入力し、著者候補を選択できる
- 対応する紙書籍が楽天Books APIの取得範囲で全件対象になる
- 初期ランダム順が追加読み込み中に変化・重複しない
- 出版年表示が定義済みの日付規則で古い順になる
- 書影あり・なしの両カードから詳細を開ける
- PCとモバイルで等幅列のmasonry表示になる
- キーボードだけで検索、表示切替、カード選択、ダイアログを操作できる
- キャッシュ済み・未取得時の性能目標を代表データで満たす
- 外部API失敗時に再試行できる
- `pnpm check`が成功する
